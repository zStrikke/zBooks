# 06 · Diagrama entidad-relación

Diseño previsto de MySQL. Se omiten `created_at`, `updated_at`, `deleted_at` y las tablas de paquetes (roles de spatie, `notifications`, `jobs`, `sessions`…).

## Núcleo: usuarios, libros y viaje

```mermaid
erDiagram
    users ||--o{ user_zones : "tiene"
    zones |o--o{ user_zones : "favorita"
    users ||--o{ books : "registra"
    users |o--o{ books : "posee"
    works ||--o{ books : "ejemplares"
    books ||--o{ releases : "liberaciones"
    users ||--o{ releases : "libera"
    users |o--o{ releases : "destinatario"
    zones |o--o{ releases : "en zona"
    books ||--o{ journal_entries : "diario"
    users |o--o{ journal_entries : "escribe"
    works ||--o{ reviews : "reseñas"
    users ||--o{ reviews : "escribe"

    users {
        bigint id PK
        varchar username UK
        varchar email UK
        varchar password
        varchar avatar
        text bio
        varchar locale
        int points_total
        tinyint level
        timestamp email_verified_at
    }
    user_zones {
        bigint id PK
        bigint user_id FK
        bigint zone_id FK "nullable"
        varchar label
        decimal lat
        decimal lng
        smallint radius_km
        enum type "home | temporary"
        date ends_at "nullable"
    }
    zones {
        bigint id PK
        varchar name
        varchar address
        varchar city
        decimal lat
        decimal lng
        varchar hours
        text description
        bool approved
        bigint created_by FK
    }
    works {
        bigint id PK
        varchar isbn UK "nullable"
        varchar title
        varchar author
        varchar language
        varchar genre
        varchar cover_url
    }
    books {
        bigint id PK
        char bcid UK
        bigint work_id FK
        bigint registered_by FK
        bigint current_holder_id FK "nullable"
        enum status
        varchar condition
        text notes
    }
    releases {
        bigint id PK
        bigint book_id FK
        bigint user_id FK
        bigint recipient_id FK "nullable"
        bigint zone_id FK "nullable"
        enum type "wild | controlled | zone"
        decimal lat
        decimal lng
        varchar place_text
        text hint
        timestamp released_at
    }
    journal_entries {
        bigint id PK
        bigint book_id FK
        bigint user_id FK "nullable"
        enum type
        text body
        decimal lat
        decimal lng
        varchar city
        bool is_anonymous
    }
    reviews {
        bigint id PK
        bigint work_id FK
        bigint user_id FK
        tinyint rating "1-5"
        text body
    }
```

## Índices y restricciones relevantes

| Tabla | Índice / restricción | Motivo |
|---|---|---|
| `books` | `UNIQUE(bcid)` | Búsqueda por BCID y unicidad |
| `reviews` | `UNIQUE(work_id, user_id)` | Una reseña por obra y usuario |
| `point_transactions` | `UNIQUE(idempotency_key)` | No duplicar puntos en reintentos |
| `releases`, `zones`, `events` | `INDEX(lat, lng)` o columna `POINT` + `SPATIAL INDEX` | Búsquedas por cercanía (se decidirá en It. 4) |
| `user_zones` | `INDEX(user_id, type)` | Obtener zona activa |
| `channel_members` | PK compuesta | Pertenencia única |
| `event_attendees` | PK compuesta + `INDEX(event_id, status)` | Contar plazas y lista de espera |
